# Slice 4: mentions dashboard

Run `pnpm db:migrate` for existing slices, `pnpm dev`, then open `/mentions` with an approved Google account. There are no slice 4 tables or migrations: existing articles, mentions, matches, clients, keywords and sites are sufficient. Use the slice 3 scanner/rematch commands to populate matches.

The active client selector resets filters when switching clients. Keyword, site, source and status filters apply to every tab and its count. Default is New, last 24h, without ignored mentions. New/All/Flagged include verified publications within the selected window and date-unverified articles whose FIRST discovery is within it. Every uncertain card always displays the exact flag "Date not verified". Use All (24h) for all workflow statuses except ignored; explicitly filter Ignored to inspect ignored matches. Last 6h/12h/24h use publication bounds for verified articles and earliest discovery for date-unverified articles, including coarse intervals straddling the selected window's lower cutoff. Rediscovery never resets first discovery; the discovery fallback never promotes confidence. New trusted publication evidence may verify an uncertain date. Show older explicitly includes history. Fully old verified publications require that control; future verified publications stay excluded. Date unverified retains all unresolved dates regardless of discovery age. Inactive clients/rules, stale keyword revisions and unreadable articles cannot appear. Site choices come only from the selected client's mentions.

Each article/client has one card and one review state, even when multiple current keywords or title/body fields matched. Excerpts highlight UTF-16 offsets in the original text, including Bangla normalization/zero-width characters. React renders excerpts as text. No clustering is performed in this slice, so older or other-client articles cannot surface as cluster representatives.

PostgreSQL evaluates every response against one statement clock, without cached feed reads. Verified recent cards use publication-bound expiry; uncertain cards in New/All/Flagged expire at first discovery plus the selected window. The browser checks the server-aligned clock every second, removes expired cards and recomputes tab counts, refreshes every minute and on focus/visibility resume. Explicit history and the Date unverified archive have no rolling expiry. Bulk actions apply atomically to 1–500 IDs in the selected client; unknown/cross-client IDs reject the whole action. Approved viewers can read; only current active admins/analysts can review. Revoked approvals are checked on every request.

Run `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm build`. Integration tests use a disposable PostgreSQL database and restricted runtime credentials. They cover verified older/future exclusions, recent unverified discovery fallback and flagging, immutable first discovery, exact cutoff ±1 microsecond through the real query, live read expiry, late discovery, 6/12/24h and explicit history, the Date unverified archive, client/keyword/site/source/status scoping, revision/extraction eligibility, counters, original Bangla highlighting, read-only roles, revocation, and atomic review/bulk operations. Unit tests cover filter validation, live expiry/counts after sleep, history, and Dhaka midnight display.

Manual browser acceptance: sign in, select clients, apply filters, switch tabs, toggle history, and run single/bulk review actions; sign in as viewer and confirm actions are absent. Confirm recent uncertain cards always show "Date not verified" in New/All/Flagged, and older unresolved cards remain in Date unverified. Leave a verified card open at its publication cutoff and an uncertain main-feed card at its first-discovery cutoff; confirm each disappears along with its main-feed count, including after backgrounding and resuming. Rediscover the uncertain article and confirm its cutoff remains unchanged. No date approval/editor, scheduler, health banners, extension, clustering or exports are implemented.
